## 4. 봇 협업 워크플로우 (핵심)

### 4-1. 산출물 저장 흐름

```
[1] 각 봇이 산출물 생성 (md + sidecar json)
    ↓
[2] 생성한 봇이 저장 후보 표시
    - frontmatter에 `obsidian_save_candidate: true` 추가
    - sidecar json에 `save_reason` 기재
    ↓
[3] 인사이트클로가 저장 후보 선별
    - 판단 기준: 재사용성 / 시계열 가치 / 후속분석 활용 / 구조적 패턴 / 맥락복원 가능
    - 탈락한 항목은 frontmatter에서 `obsidian_save_candidate: false`로 변경
    ↓
[4] 인사이트클로가 옵시디언에 저장
    - 적절한 폴더에 md + json 배치
    - 허브 문서에 링크 추가
    - 인덱스 갱신
    ↓
[5] 주간/월간 정리
    - 주 1회: 중복 메모 → 허브 흡수, 임시 노트 제거
    - 월 1회: 전체 재분류, importance 재평가
```

### 4-2. 봇별 역할 상세

| 봇 | 역할 | 하는 일 | 안 하는 일 |
|----|------|---------|------------|
| **마스터클로** | 조율·통합 | 통합 보고서 생성, 저장후보 표시, 인사이트클로에 저장 지시 | 직접 옵시디언 저장 안 함 |
| **데이터클로** | 수집·적재 | 수집 결과 md+json 생성, 저장후보 표시 | 직접 옵시디언 저장 안 함, 원본 PDF 옵시디언에 안 넣음 |
| **인사이트클로** | 선별·가공·저장 | 저장 판단, md+json 가공, 태그 부여, 허브 연결, 인덱스 갱신, 주간/월간 정리 | 수집, 크롤링, 통합 판단 안 함 |

### 4-3. 저장 후보 판단 기준 (전 봇 공통 — 5가지 체크리스트)

산출물 생성 시 아래 5가지 중 **2개 이상 해당**되면 `obsidian_save_candidate: true` 표시:

1. ✅ **재사용 가능성**: 6개월 뒤에도 참고할 가치가 있는가?
2. ✅ **시계열 비교 가치**: 과거/미래 데이터와 비교할 의미가 있는가?
3. ✅ **후속 분석 활용**: 다른 봇이나 다음 작업에서 바로 쓸 수 있는가?
4. ✅ **구조적 패턴/결정**: 일회성 로그가 아니라 규칙이나 패턴이 담겨있는가?
5. ✅ **맥락 복원**: md/json 요약만으로 원래 상황을 재구성할 수 있는가?

### 4-4. 중요도 분류

| 등급 | 기준 | 보존 기간 | 예시 |
|------|------|-----------|------|
| **L1-핵심** | 운영 규칙, 장기 thesis, 반복 패턴 | 영구 | 투자 핵심 논점, 운영 원칙, 실패 복기 |
| **L2-참조** | 일일보고, 분석 결과, 브리핑 | 3개월 후 허브 흡수 검토 | 일일보고, 기업 분석, 시장 브리핑 |
| **L3-임시** | 단발 수집, 초안, 확인 로그 | 주간 정리 시 삭제 | 크롤링 원본 요약, 임시 메모, 테스트 결과 |

## 5. 구현해야 할 스크립트

### 5-1. `scripts/obsidian_save.py` — 옵시디언 저장 유틸리티

인사이트클로가 호출하는 핵심 스크립트.

**기능**:
- md + sidecar json을 받아서 적절한 옵시디언 폴더에 저장
- 파일명 규칙 적용: `YYYY-MM-DD_봇이름_주제.md`
- frontmatter 검증 (필수 필드 체크)
- ticker가 있으면 canonical_tickers.json에서 정규화
- 기업 허브가 없으면 자동 생성
- 인덱스 자동 갱신

**인터페이스** (예시):
```bash
python3 scripts/obsidian_save.py \
  --source "/path/to/report.md" \
  --sidecar "/path/to/report.json" \
  --category "일일보고" \
  --bot "마스터클로" \
  --importance "L2"
```

**출력**: 저장된 옵시디언 경로, 갱신된 인덱스 항목

### 5-2. `scripts/obsidian_index.py` — 인덱스 갱신

**기능**:
- `인덱스/전체인덱스.md` 갱신 (날짜별 산출물 목록)
- `인덱스/태그맵.md` 갱신 (태그별 문서 연결)
- `인덱스/기업목록.md` 갱신 (ticker → 허브 경로)

**인터페이스**:
```bash
python3 scripts/obsidian_index.py --rebuild   # 전체 재구축
python3 scripts/obsidian_index.py --update    # 마지막 갱신 이후 변경분만
```

### 5-3. `scripts/obsidian_cleanup.py` — 주간/월간 정리

**기능**:
- L3 임시 노트 중 7일 이상 경과한 것 삭제 (또는 `_meta/archive_log.json`에 기록 후 삭제)
- 중복 문서 탐지 (같은 ticker + 같은 날짜 + 유사 제목)
- 월간 importance 재평가 후보 목록 생성

**인터페이스**:
```bash
python3 scripts/obsidian_cleanup.py --weekly   # 주간 정리
python3 scripts/obsidian_cleanup.py --monthly  # 월간 정리
python3 scripts/obsidian_cleanup.py --dry-run  # 미리보기만
```

## 6. 전 봇 워크스페이스 반영 사항

### 6-1. 각 봇의 AGENTS.md 또는 공통 규칙에 추가할 내용

```markdown
## 옵시디언 저장 협업 규칙

### 산출물 생성 시 (전 봇 공통)
- 모든 산출물은 `md + sidecar json` 쌍으로 생성한다.
- 저장 후보 판단: 5가지 체크리스트 중 2개 이상 해당 시 frontmatter에 `obsidian_save_candidate: true` 표시.
- 중요도(L1/L2/L3)를 frontmatter `importance` 필드에 기재.
- 기업 관련 산출물은 반드시 `ticker` 필드를 포함 (canonical_tickers.json 참조).

### 저장 담당 (인사이트클로 전담)
- 옵시디언 저장은 인사이트클로만 수행한다.
- 다른 봇은 저장 후보를 표시하고, 인사이트클로가 최종 판단하여 저장한다.
- 마스터클로가 인사이트클로에게 저장 지시를 내릴 수 있다.

### 허브 우선 원칙
- 개별 메모를 늘리기보다 허브 문서(기업허브/주제허브)에 연결한다.
```

## 8. 주의사항

1. **기존 `OpenClaw/` 폴더 구조 유지**: 이미 MEMORY.md에 정의된 `일일보고/`, `기업분석/` 등 6개 폴더는 그대로 유지. 새 폴더를 추가만 한다.
2. **옵시디언 `.obsidian/` 폴더 건드리지 않기**: Vault 설정은 사용자 영역.
3. **스크립트 경로**: `~/.openclaw/workspace/scripts/` 아래에 생성.
4. **ticker 정규화 필수**: 기업 관련 문서는 반드시 정규화된 ticker를 사용해야 중복 방지.
5. **파일명 규칙**: `YYYY-MM-DD_봇이름_주제.md` (한글 가능, 공백은 밑줄로).
6. **원본 분리**: 옵시디언에 PDF/이미지/대용량 파일 직접 넣지 않기.
