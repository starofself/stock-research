# 🔬 오늘의 AGENTS.md & AI 에이전트 코딩 트렌드

## 주요 뉴스/업데이트
- **공식 AGENTS.md 신호는 “신규 코드 변경”보다 “생태계 확장” 쪽이 강했다.** agents.md 공식 사이트는 현재 `60k+` 오픈소스 프로젝트 채택을 전면에 내세우고 있고, AGENTS.md를 AAIF(Linux Foundation 산하 Agentic AI Foundation) stewardship 하의 오픈 포맷으로 소개한다.
- **GitHub 저장소 자체는 최근 24시간 내 신규 커밋/릴리즈는 확인되지 않았다.** 다만 repo `updated_at`은 2026-04-05 02:43 UTC로 갱신됐고, 최근 공개 PR 활동으로는 `#171 Add GitHub Actions workflow for NodeJS with Webpack`가 2026-04-04 22:40 UTC에 close됐다. 즉, 당일 핵심 신호는 코드 릴리즈보다 운영/문서/채택 확장이다.
- **OpenAI Codex 문서 축에서 AGENTS.md 주변 기능이 더 구조화되고 있다.** 최근 문서에서 Plugins는 `skills + app integrations + MCP servers` 묶음으로 설명되고, pricing 문서도 nested AGENTS.md와 MCP 수를 컨텍스트/비용 관리 포인트로 직접 언급한다. 이는 AGENTS.md가 단독 파일이 아니라 skill/MCP/plugin과 함께 쓰는 조합형 표준으로 굳어지는 흐름이다.
- **AAIF 새 발표(4/2)**: Linux Foundation 보도자료 기준 AAIF가 2026 글로벌 이벤트 프로그램을 발표했고, MCP·goose·AGENTS.md를 개발자 행사 핵심 기술로 명시했다. 서울 MCP Dev Summit(8월)도 포함돼 있어 아시아 생태계 확산 신호가 뚜렷하다.

## 논문/연구 하이라이트
- **arXiv 2601.20404 — _On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents_**
  - 10개 저장소, 124개 PR 비교.
  - AGENTS.md 존재 시 **중앙값 runtime -28.64%**, **output token -16.58%**.
  - 해석: AGENTS.md는 단순 “설명 문서”가 아니라 에이전트 작업비용을 줄이는 운영 artifact로 볼 근거가 생겼다.
- **arXiv 2602.14690 — _Configuring Agentic AI Coding Tools: An Exploratory Study_**
  - 2,923개 GitHub repo 분석.
  - 결론: repository-level context files가 여전히 압도적이며, **AGENTS.md가 도구 간 상호운용 표준으로 부상**. 반면 Skills/Subagents는 아직 얕게 채택되는 단계.
  - 해석: 당분간 보급의 첫 관문은 AGENTS.md이고, skill/subagent는 상위 고도화 계층으로 남을 가능성이 높다.
- **OpenAI OSS maintenance 사례(1개월 전이지만 실무 시사점 큼)**
  - OpenAI Agents SDK 운영에서 repo-local skills + AGENTS.md + GitHub Actions 조합으로 3개월간 merged PR 수가 **316 → 457**로 증가.
  - 해석: 실무 현장에서는 “AGENTS.md 단독”보다 “AGENTS.md로 기본 정책 고정 + skills로 반복 workflow 캡슐화”가 생산성 패턴으로 자리잡는 중.

## OpenClaw 시스템 적용 시사점
1. **AGENTS.md를 “정적 규칙 파일”이 아니라 비용 절감 장치로 봐야 한다.** 논문 결과대로면 긴 작업일수록 repo-level 지시문 품질이 runtime/token 양쪽을 줄일 가능성이 높다.
2. **OpenClaw도 계층 분리를 더 분명히 유지하는 쪽이 맞다.**
   - AGENTS.md: 전역 운영 원칙·역할·승인 경계
   - SKILL.md: 반복 workflow
   - MCP/플러그인: 외부 도구 연결
   이 3층이 섞이면 문맥이 비대해지고 유지보수성이 떨어진다.
3. **Nested AGENTS.md 전략이 유효하다.** 공식 사이트가 monorepo용 nested AGENTS.md를 권장하고 있어, OpenClaw도 향후 하위 프로젝트/스킬 묶음별 로컬 AGENTS.md를 두는 방식이 확장성 측면에서 맞다.
4. **AAIF 일정은 표준 고착화의 선행지표다.** MCP와 AGENTS.md가 함께 행사 핵심 트랙으로 묶였다는 것은, 향후 개별 도구 경쟁보다 상호운용 규약 경쟁이 더 중요해진다는 뜻이다.
5. **오늘 결론:** AGENTS.md 자체의 “새 릴리즈”는 없었지만, **표준의 무게중심이 채택·연구·재단 거버넌스 쪽으로 이동 중**이다. OpenClaw는 이미 이 방향과 잘 맞물려 있으므로, 앞으로는 AGENTS.md 품질관리와 skill 분해 기준을 더 엄격히 가져가는 편이 유리하다.
