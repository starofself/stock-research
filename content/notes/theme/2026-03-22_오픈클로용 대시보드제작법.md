- 외부 의존성은 가능하면 추가하지 마라.
- 새 설치 사용자도 `python3 panel/server.py` 정도로 바로 띄울 수 있게 해라.
새로 OpenClaw를 설치한 사람도 그대로 쓸 수 있는 형태로 OpenClaw 운영 대시보드를 구현해줘.

목표:
- 모든 봇을 한눈에 볼 수 있는 로컬 운영 현황판을 만든다.
- 각 봇의 기본 설정과 현재 세션 오버라이드를 한 화면에서 보고 수정할 수 있게 한다.
- context 상태, /new 필요 여부, 기타 운영상 문제 신호까지 볼 수 있게 한다.
- 특정 사용자 PC 경로나 특정 계정명에 하드코딩되지 않게 만들어라.

중요 원칙:
- 절대경로를 하드코딩하지 마라.
- 특정 사용자명(`/Users/xxx/...`)에 의존하지 마라.
- 새로 OpenClaw를 설치한 사람도 자기 환경에서 바로 실행할 수 있게 해라.
- 질문은 정말 막힐 때만 하고, 가능하면 스스로 탐색해서 끝까지 구현/검증해라.
- 설명만 하지 말고 실제 파일 수정, 실행, 검증까지 끝내라.

구현 위치:
- 현재 열려 있는 workspace 루트 아래에 `panel/` 디렉터리를 만들어 구현
- 예:
  - `panel/server.py`
  - `panel/static/index.html`
  - `panel/static/app.js`
  - `panel/static/styles.css`
  - 가능하면 `panel/README.md`도 만들어서 처음 설치한 사람이 실행 방법을 바로 알 수 있게 해라

경로/환경 처리 방식:
- `Path.home()`, `~`, 환경변수, 현재 workspace 기준 상대경로를 사용해라.
- OpenClaw 상태 디렉터리/설정 파일은 하드코딩하지 말고 가능한 순서대로 탐지해라:
  1. `OPENCLAW_CONFIG_PATH`
  2. `openclaw config file`
  3. `OPENCLAW_STATE_DIR`
  4. 기본값 `~/.openclaw/openclaw.json`
- OpenClaw 바이너리도 하드코딩 최소화:
  1. PATH의 `openclaw`
  2. 없으면 `~/.openclaw/bin/openclaw`
- `--profile`, `--dev`, 커스텀 state dir을 쓰는 사용자도 가능하면 대응해라.
- “이 컴퓨터의 agent 이름”을 전제로 짜지 말고, 실제로 읽힌 agent 목록을 기준으로 동작하게 해라.

권장 구현 방식:
- 백엔드는 Python 표준 라이브러리 기반 HTTP 서버로 가볍게 구현해도 좋다.
- 프론트는 바닐라 JS/CSS로 구현해도 된다.

데이터 소스:
- 탐지된 OpenClaw config 파일
- `openclaw agents list --json`
- `openclaw models status --agent <id> --json`
- `openclaw models list --json`
- `openclaw gateway call sessions.list --json --params '{"limit":200}' --token <token>`
- 세션 수정은 `openclaw gateway call sessions.patch ...`
- 게이트웨이 재시작은 `openclaw gateway restart --json`

반드시 구현할 기능:

1. 전체 요약 영역
- agent 수
- live session 수
- bindings 수
- 기본 모델
- gateway mode
- gateway auth mode
- telegram enabled 여부 정도를 한눈에 보이게

2. 봇별 기본 설정 수정
- bot name
- default model
- workspace
- identity name
- creature / role
- vibe / theme
- emoji
- default bot 여부
- 이 값들은 config 파일과 필요한 경우 각 workspace의 `IDENTITY.md`에 반영되게 해라.

3. 봇별 라이브 세션 설정 수정
- session label
- model override
- thinkingLevel
- reasoningLevel
- verboseLevel
- fastMode
- responseUsage
- 이 값들은 `sessions.patch`로 즉시 반영되게 해라.

4. 운영 상태 / 문제 신호 표시
각 봇마다 아래를 계산해서 별도 칸으로 보여줘:
- 대표 세션의 context 사용률(%)
- /new 필요 여부
- 지금 계속 써도 되는지 / 새 주제 전환 시 /new 권장인지 / 지금 /new를 강하게 권장하는지
- totalTokensFresh=false 같은 stale 상태
- abortedLastRun 여부
- auth 만료 임박 여부
- 바인딩 없음 여부
- live session 없음 여부
- 기타 눈에 띄는 문제를 `Issues & actions` 형태로 보여줘

운영 판단 로직도 구현해라:
- context 사용률 높으면 warning/error
- 예: 65% 이상이면 /new 권장, 85% 이상이면 /new 강권
- usage 정보를 계산 못하면 unknown 상태
- auth remainingMs가 짧으면 경고
- bindings 없으면 info 이슈
- 문제 tone은 success / info / warn / error로 시각화

5. 세션 카드에 꼭 보여줄 정보
- session key
- display name
- model
- total tokens / context tokens
- usagePercent
- updatedAt 또는 상대 시간
- channel / account
- kind / chatType
- 현재 thinking / reasoning / verbose / fast 상태
- context health와 추천 액션

6. UI 요구사항
- 데스크톱에서 봇 카드가 한 줄에 최대 2개만 보이게 해라
- 모바일은 1열
- 카드 내부는 다음 순서로 정리:
  - 상단 요약
  - context / issues
  - 기본 설정
  - live sessions
- 너무 복잡하지 않게, 한눈에 들어오게 정리해라
- 상태 색상은 success/info/warn/error 톤으로 구분
- session 영역도 토글류(thinking/reasoning/verbose/fast)와 기타 입력(label/model override/usage footer)을 분리해서 보기 좋게 해라

7. 성능
- `/api/state`는 OpenClaw CLI 호출이 느릴 수 있으니 병렬화해라
- 상태 응답은 짧은 TTL 캐시(예: 5초)를 둬라
- config 저장, session patch, gateway restart 후에는 캐시 무효화해라
- 첫 로드는 느릴 수 있어도, 연속 새로고침은 빨라야 한다

8. API
아래 엔드포인트 정도는 제공해라:
- `GET /api/state`
- `POST /api/defaults`
- `POST /api/agent`
- `POST /api/session`
- `POST /api/restart`
